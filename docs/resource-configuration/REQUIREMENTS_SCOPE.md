# 统一资源配置与 Agent 运行规则：需求范围 V1.0

日期：2026-09-10。需求负责人：根协调 Agent。状态：用户已明确同意独立资源页面、Agent 模型下拉，以及同时支持自定义 HTTP 工具；本文件作为项目经理排期、产品细化、开发和验收的范围基线。

## 1. 目标与交付流程

让用户通过页面管理模型、工具、MCP 服务和技能，再为各个 Agent 选择资源并启用，使页面配置实际决定后端运行行为。不能仅新增页面或保存字段而不接入执行链路。

工作流程：项目经理制定计划 → 产品 Agent 输出 PRD 和交互原型 → 全栈架构师输出架构/前后端详细设计并开发、自测 → 测试工程师执行独立测试、推动缺陷修复并回归 → 产品 Agent 验收并出报告 → 项目经理结项。需求细化、测试设计与实现可在依赖明确时并行；阶段未通过不得记为完成。沿用既有四个协作角色，不要求用户再次创建或重述需求。

交付要求：范围—需求—实现—测试—验收有可追溯关系；本轮范围内无未关闭 P0/P1。阻塞必须说明已完成部分、具体原因和后续动作，不能以模拟接口通过代替真实环境通过。

## 2. 当前基线与需要补齐的差距

- 已有 Agent 创建、草稿、发布、启停、主子关联和试运行；原有可用功能必须回归。
- 已有 Kimi K3 专用适配与 OpenAI 独立启动配置，但运行时主要为全局模型，Agent 模型字段未真正控制每个 Agent 的模型选择。
- 内置工具和技能主要来自代码目录；现有 MCP 为固定 HTTP 桥，不能将该桥目录改名后当作标准 MCP 服务管理完成。
- Agent「策略」包含权限、执行次数、记忆与检索等混合字段，其中一些配置尚未影响执行。
- 默认使用已配置 Kimi 与本地关键词知识检索；OpenAI 未充值。本轮不自动调用 OpenAI，不把其在线可用性列为已经验证。
- 运行方式沿用本地单实例；现有客服订单等仍为模拟业务，接入自定义 HTTP 工具不等于已经接入真实企业系统。

## 3. 页面与导航范围

左侧一级导航为「Agents」「模型」「工具」「MCP」「技能」。统一列表、搜索、状态过滤、详情/编辑、保存草稿、启用/停用、错误提示、空状态与引用关系展示。资源管理页面负责定义资源，Agent 页面负责关联和授权，避免两处维护同一资源定义。

适配常用桌面窗口和窄屏；保留已有管理页入口和 Agent 链接可达性。中文标签与帮助文字优先，不直接以内部字段名充当操作说明。

## 4. 模型配置

1. 支持新增、编辑、查看、启停、设为系统默认、查看引用 Agent；支持多个同供应商配置并存。
2. 配置字段：名称、简介、供应商（OpenAI / Kimi）、接口地址、模型标识、凭证、支持能力、请求超时及供应商支持的默认参数。
3. Kimi 沿用 kimi-k3 及正确工具回合协议，参数表单按供应商能力展示；不能把不支持的温度、推理开关等作为可生效参数暴露。OpenAI 保留现有兼容路径。
4. 凭证支持页面录入/替换和引用已有服务端环境变量。原文不返回浏览器，不进入日志、审计、导出、URL 或页面源代码；页面仅显示已配置状态或掩码。留空表示保留，清除需明确动作；数据库存储凭证须加密，解密密钥不与密文同库保存。
5. 提供「测试连接」，明确区分未测试、测试成功、鉴权失败、模型不可用、超时/网络异常；保存配置不自动发推理请求。测试使用极短输入并标明可能产生模型用量，OpenAI 本轮只用模拟服务验证。
6. Agent 模型下拉选择已启用配置，显示名称/供应商/模型；支持「使用系统默认」。每个 Agent 独立选择，同一进程可同时使用不同供应商，不通过重启切换整个应用。
7. Agent 可选择继承模型默认参数；若开放覆盖，只允许供应商支持并验证范围的参数。列表、详情、试运行和会话诊断展示实际生效模型，不显示一个值却运行另一个值。
8. 迁移现有 Kimi/OpenAI 配置：复用服务端凭证引用，不复制真实 Key 到种子或文档；既有 Agent 缺省关联系统默认，升级后不丢失可用性。OpenAI 可保存为未启用配置。

## 5. 工具配置（包含自定义 HTTP 工具）

统一工具目录，区分「内置」「HTTP」「MCP」来源，并显示名称、简介、标识、输入参数、只读/写入属性、启用状态和引用关系。MCP 来源工具定义由对应服务同步，不在工具页重复编辑其协议定义。

### 内置工具

保留现有查单、物流、工单、瑕疵补偿等工具；展示其能力和参数，可控制全局启停。执行实现及基础风险属性由代码提供，不允许通过页面随意修改成另一段代码。允许维护展示信息及更严格的执行规则。

### 自定义 HTTP 工具

1. 通过页面新建、编辑、启用并测试 HTTP 工具，无需新增 Java 方法。支持 GET、POST、PUT、PATCH、DELETE，JSON 请求/响应。
2. 字段包含名称、简介、稳定标识、URL、请求方法、输入参数 Schema、路径/查询/Header/JSON Body 参数映射、认证方式、超时、响应提取、只读/写入属性及确认要求。
3. 认证至少支持无认证、Bearer、API Key Header；凭证处理遵循模型凭证规则。调用输入不能覆盖认证 Header、服务器地址或执行规则。
4. 参数映射采用声明式字段映射/模板；响应提取支持明确的字段路径，能处理嵌套对象、列表、缺失字段。第一版不支持任意 JavaScript/Python/SQL 执行。
5. 区分 HTTP 状态错误、超时、响应非 JSON、参数错误和映射失败，返回可理解的工具失败信息；限制响应体大小与工具结果长度。写请求默认不自动重试，避免重复业务操作。
6. 连接目标由管理员配置；模型只能填写定义好的业务参数，不能任意指定目标 URL。禁止协议绕过、凭证跨域重定向和访问云元数据等保留端点；确有本地/内网业务接口需求时采用明确配置的目标授权，不能一刀切禁止项目自身的本地测试服务。
7. 测试入口显示即将执行的参数；写工具测试也进入明确的确认流程，不通过「测试」绕过执行规则。独立测试使用项目自有模拟 HTTP 服务，不操作真实订单。
8. 启用后 Agent 可选择并实际调用；停用后新的调用立即拒绝。展示调用成功/失败、耗时和脱敏的输入输出摘要。

## 6. MCP 服务配置

1. 新增、编辑、查看、启停多个独立服务，字段包含名称、简介、传输类型、服务地址、认证、超时及连接状态。
2. 第一版支持标准 MCP Streamable HTTP：完成必要的初始化、工具发现与工具调用，并处理会话/错误；保留现有项目 HTTP 桥为明确标识的兼容类型。架构师依据官方协议定义适配与测试，不能把桥接口当作标准协议验收。
3. 提供连接测试、同步工具和最近同步结果；显示新增、变更、移除的工具。同步失败保留上次已发布目录，标识异常，不清空所有资源。
4. 工具采用「服务 ID + 工具名」确定唯一身份，避免不同 MCP 服务同名工具冲突；模型侧名称映射必须可逆、稳定。
5. Agent 可以选择服务并勾选服务内允许使用的工具，不能因为关联服务就无条件开放未来新增工具。
6. MCP 工具缺乏可靠风险说明时默认按写入/需确认处理，可由管理员配置更严格或经核实的属性。MCP 与 HTTP、内置工具遵循同一授权、确认、次数、超时及审计规则。
7. 服务停用、工具移除、认证失败或连接失效时有明确提示；不能静默转向另一服务或调用未授权工具。
8. 第一版不支持从页面启动任意本地进程、安装软件包或 stdio 命令，也不承诺兼容所有历史 MCP 传输方式。

## 7. 技能配置

1. 支持自定义技能的新增、编辑、查看、发布、启停及版本记录，保留已有清晰表达、订单查询、知识检索技能。
2. 字段包含名称、简介、技能指令、适用 Agent 类型、依赖工具（包括 HTTP/MCP）、是否需要知识检索及使用说明。
3. 技能是可复用的指令和能力组合，不是任意代码包。第一版不提供上传并执行任意脚本/安装第三方技能包。
4. Agent 勾选技能时展示引入的工具和检索能力，合并重复工具；依赖工具仍受运行规则约束，技能不能绕过写权限或确认要求。
5. 技能修改发布新版本，不悄悄扩大所有引用 Agent 的权限。Agent 显示已绑定版本、有新版本可更新及差异，更新依赖进入 Agent 草稿，重新发布才生效。
6. 依赖资源缺失、停用或变更导致不兼容时阻止启用，并定位到具体依赖；引用关系页面支持定位受影响 Agent。

## 8. Agent 页面与运行规则

Agent 编辑建议分为「基本信息」「提示词」「模型与能力」「子 Agent（仅主 Agent）」「运行规则」「发布与试运行」。最终布局由产品原型确认，但以下功能不可遗漏：

- 名称、简介、提示词、类型；模型配置下拉；工具/技能/MCP 授权选择；依赖和当前实际生效资源汇总。
- 将「策略」更名为「运行规则」，使用中文说明。知识检索移至能力区，不与权限和执行上限混为一谈。
- 操作权限：允许修改业务数据、需要确认的工具。写工具默认需确认，允许配置更严格规则；主 Agent 本轮仍不直接执行写工具。
- 统一确认拦截必须在实际执行工具前发生，覆盖内置、HTTP、MCP，而不是只识别用户文本里的“取消订单”。服务端保存待确认的工具身份、参数和资源版本；确认时重新校验权限和状态，防止参数篡改和重复执行。
- 执行限制：最大工具调用轮数、单工具超时和单任务总超时；多工具一轮的计数定义在 PRD/设计中明确。达到上限后停止并给出原因，不能继续无限循环。
- 主 Agent 显示最大子 Agent 转交次数；本轮范围为单层主子结构，限制实际转交次数，不引入多层嵌套 Agent 或无限递归。若当前一轮只允许一次转交，则页面与后端均明确该限制，不能提供一个无效数字输入。
- 会话记忆：是否注入摘要、保留多少轮历史；Agent 级设置实际影响送给模型的上下文并有测试证据。跨 Agent 历史如何隔离/共享由 PRD 明确。
- 试运行与正式会话使用相同资源解析和权限执行逻辑，展示实际模型、工具调用、耗时与错误。补齐本轮工具调用轨迹汇总，不能继续用空 toolCalls 掩盖实际执行。

## 9. 配置生命周期、引用与持久化

1. 所有资源持久化；重启后已发布状态及引用可恢复。新增稳定 ID，显示名称可修改，引用不能因重命名断裂。
2. 「保存草稿」不影响线上版本；「启用/发布」校验完整依赖后原子生效，不要求重启。模型/工具/MCP 的配置发布会影响其引用者，发布前展示影响范围与差异；已开始的请求固定其配置快照，新请求使用新发布版本。
3. 技能采用明确版本绑定和显式升级，避免间接权限扩大。系统默认模型变更影响选择「系统默认」的 Agent，操作前显示受影响对象。
4. 停用是全局可用性开关：展示影响范围并确认后，阻止新的请求和新的工具执行；已发出的外部请求不能保证撤销，UI 与设计应明确边界。待确认写操作须在执行前重新检查。
5. 被 Agent/技能引用的资源不可直接删除，显示引用清单；解除引用后才能删除。停用不等于删除，禁止静默改用其他模型或工具。
6. 配置失败、重复标识、并发编辑冲突、依赖失效等情况不能导致已运行版本部分更新。配置审计记录操作者上下文、时间、动作与脱敏差异，但不把现有 Demo Header 角色当作生产身份认证。
7. 迁移现有 Agent/资源与本机模型配置，保留历史草稿和已发布配置；必要迁移必须可重复执行并有回退说明。真实密钥不得进入迁移脚本或提交文件。

## 11. 明确不包含

本轮不开发生产 SSO/RBAC/多租户计费、多实例同步、复杂可视化工作流、主子多层嵌套、任意脚本运行、完整技能包市场、自动安装软件、真实企业业务系统接入、知识库体系重做、OpenAI 充值操作或生产部署。Kimi 上游逐 token 输出保持后续项，当前缓冲 SSE 需如实标识。

上述边界不免除本轮密钥管理、HTTP/MCP 目标控制、写操作确认、配置一致性和功能回归要求。不得以范围外说明掩盖本轮新增的配置不生效问题。

## 12. 项目经理接收与推进要求

项目经理收到后直接开展排期和角色调度，不再就用户已明确同意的范围重复索要确认。先输出阶段计划、依赖、负责人、工时估计和验收门禁；产品完成 PRD/原型后推进设计、开发、自测、独立测试、修复、产品验收和结项。

文档集中在 `docs/resource-configuration/`，至少包含 PROJECT_PLAN、PRD、PROTOTYPE、ARCHITECTURE、DETAILED_DESIGN、SELF_TEST_REPORT、TEST_PLAN、TEST_REPORT、ACCEPTANCE_REPORT 和最终交付/迁移说明。实际结果不足时如实标记，不提前填通过。

当前 8080 是用户已启动的应用。开发使用独立测试端口和数据目录；验证通过后再安排更新正常应用，避免将测试资源与示例写操作混入用户数据。若确需停止正常服务，先说明原因并控制中断，不未经验证直接替换其运行配置。
