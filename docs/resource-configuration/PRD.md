# 统一资源配置与 Agent 运行规则 PRD

版本：R1 / 1.0；日期：2026-09-10；责任人：产品 Agent。

前置：[REQUIREMENTS_SCOPE.md](REQUIREMENTS_SCOPE.md) V1.0、[PROJECT_PLAN.md](PROJECT_PLAN.md) R0 已完成。本文件与 [PROTOTYPE.html](PROTOTYPE.html) 构成 R1 产品交接，开发及测试结果尚未产生。范围完整覆盖 RC01–RC15，不沿用上一迭代将工具轨迹、执行预算或记忆列为范围外的结论。

## 1. 产品目标与成功路径

用户先在「模型、工具、MCP、技能」页面定义可用资源，再在「Agents」关联并授权，发布后配置立即决定实际模型目标、提示词、工具、检索、确认和执行预算。同一进程可运行不同供应商/模型的 Agent，无需重启切换全局提供方。

代表性任务：配置两个模型并测试 → 创建带参数映射的 HTTP 工具 → 连接标准 MCP 并发布已发现工具 → 创建依赖这些工具的技能 v1 → 为主/子 Agent 选择各自模型、技能、精确工具授权和运行规则 → 启用 → 正式对话或试运行 → 在写操作前确认具体动作 → 查看实际模型、工具轨迹和结果。

另一条任务：编辑资源草稿 → 查看差异及引用影响 → 发布新版本 → 新任务使用新版本，正在执行的任务继续使用已选快照；技能新版本必须由引用 Agent 显式更新并重新发布。紧急停用可阻止后续请求/执行，不能声称撤回已经发送的外部请求。

本轮不开发生产 SSO/多租户、多实例同步、嵌套 Agent、任意脚本执行、完整技能包市场、企业业务系统或知识库体系重做。当前 8080 用户应用不得用于产品原型或测试；开发使用隔离端口/数据。产品不读取 `.env` 或调用真实 API；极少量 Kimi 在线验证由根协调执行，OpenAI 只做模拟协议验证。

## 2. 信息架构及统一交互

左侧一级导航固定为 **Agents、模型、工具、MCP、技能**。可保留原 hash 入口兼容跳转。窄屏导航折叠为可展开菜单或横向分组，详情单列，长表单内部可滚动，提交按钮始终可达。中文业务名称优先，稳定标识和来源作为辅助信息。

五页均包含搜索、状态筛选、资源列表、空状态/加载/错误/重试、创建或允许的编辑入口、详情、引用关系、保存草稿、发布/启用、停用。列表显示名称/简介/类型或来源、当前发布版本、状态、草稿变更标记和必要诊断。详情共享「配置」「引用」「版本/审计」结构，可按资源增加配置区块。

主操作使用明确词语：新资源「创建草稿」；已有资源「保存草稿」；初次「启用并发布」；运行资源「发布更新」；停用资源「重新启用」；任何操作成功后以服务端结果刷新。草稿和运行状态分开，不以开关选中代表真实加载成功。加载失败不显示空列表；操作失败保留用户输入；保存冲突显示版本已更新，并允许复制当前草稿后重新加载，不静默覆盖。

发布确认面板必须展示当前/目标版本、脱敏字段差异、直接及间接引用对象、影响生效时点和校验错误。默认模型切换和停用使用对应影响面板；被引用资源删除按钮禁用并提供「查看引用」。不是每次输入都弹确认，只有具实际影响的发布/默认切换/停用/清除凭证/写工具执行确认需要明确操作。

权限沿用当前演示角色：viewer 只读；editor 创建、编辑草稿及安全的只读试运行；publisher/admin 发布、启停、默认模型选择、删除未引用资源、凭证变更及目标授权。任何写工具测试/试运行仍必须满足 publisher/admin 的资源操作权限（如相关）和 Agent 执行授权，并走统一写确认；角色头仍不代表生产身份认证。连接测试/同步目录由 editor 及以上发起，不能借此修改已发布目录。

## 3. 稳定身份、版本和运行快照

### 3.1 身份与引用

每种资源都有不可变 ID 与稳定 code，名称/简介可改，重命名不改变绑定。列表显示人类名称，详情可复制 ID/code。模型、工具、MCP 持有版本化配置；Agent 引用其稳定身份并在任务开始时解析已发布版本。技能引用必须包含 `技能ID + 已发布版本`，不是跟随 latest。

HTTP/内置工具与 MCP 工具使用统一身份空间。MCP 工具真实身份为「服务 ID + 原始工具名」，模型侧可编码为符合模型要求的唯一名称，编码稳定、可逆；界面始终展示服务名、原工具名和唯一身份。技能依赖记录工具身份，MCP 工具授权不得只保存同名字符串。

### 3.2 保存、发布和请求边界

| 操作 | 线上影响 | 页面说明 |
| --- | --- | --- |
| 保存草稿 | 无影响；完整持久化但不进入运行目录 | “草稿已保存，发布后生效” |
| 模型/HTTP工具/内置工具规则/MCP配置发布 | 校验全部依赖后原子更新；新任务使用新发布版本 | 展示全部引用 Agent/技能、权限/地址/模型等变更 |
| 技能发布新版本 | 产生可选版本，既有 Agent 继续绑定旧版 | 显示“有新版本，可更新”，不自动扩大权限 |
| Agent 更新技能 | 版本差异和新增/移除工具展示，接受后写入 Agent 草稿 | 再发布 Agent 才生效 |
| 系统默认模型切换 | 新任务中选择“系统默认”的 Agent 使用新默认 | 展示所有受影响 Agent；固定模型引用不变 |
| 资源停用 | 新任务及后续新工具执行拒绝；既有外部请求不能保证撤销 | 显示引用影响，明确“不自动改用其他资源” |

“一个任务”指一次用户输入经主 Agent、最多一次子转交、模型/工具循环到最终输出或等待确认的完整工作。开始时固定 Agent 发布版本、模型配置、被授权的工具/MCP配置、技能绑定版本及规则；转交不能在中途混入新发布的模型或工具配置。模型/资源发布后旧任务可继续原快照，但每次新模型调用、工具执行、子转交前必须检查当前全局启用状态及 Agent 当前可用性。**停用优先于旧快照。** 已经发出的网络请求不保证可撤销，超时应尽力取消等待并禁止继续派生动作。

停用资源可被已发布 Agent/技能引用；展示“依赖停用”而不是偷偷解绑或回落。对依赖失效的 Agent，试运行/新执行应在开始前失败并定位路径；重新启用/发布需完整校验。停用被主引用的子 Agent 延续既有规则：允许停用，主运行过滤，零可用子时明确说明。

全局停用某技能意味着即便 Agent 绑定旧技能版本也不可继续使用；启用新版技能不自动更新 Agent 绑定。资源删除要求所有草稿/当前发布 Agent 和技能引用均解除；用于审计/回滚的历史版本只保留不可执行墓碑引用，不做级联删除，历史回滚遇到已删除依赖必须失败并定位。实际已发出的外部动作不能通过回滚配置撤销。

失败、重复标识、并发冲突、依赖失效必须无部分生效；成功响应应包含已发布版本/加载状态。审计保存操作者上下文、时间、动作、版本和脱敏差异；凭证仅记录“新增/替换/清除/引用变化”，不记录原文或可恢复片段。

## 4. 模型页面（RC02、RC03）

列表：名称、供应商/模型、是否默认、启用版本、凭证状态、最近连接结果、引用数。支持同一供应商多个配置。详情包含名称、简介、供应商（OpenAI/Kimi）、接口地址、模型标识、能力（普通对话/工具，其他仅已实现可选）、请求超时、支持的默认参数和凭证。

按供应商隐藏不支持参数，服务端仍拒绝非法字段。Kimi 保持 K3 正确工具历史/推理协议，不提供“关闭思考”或不支持的温度控制；OpenAI 使用其兼容参数。Agent 初期可选择「继承模型默认参数」，如开放覆盖必须明确显示继承/覆盖和有效值、供应商约束，不能保存一个值运行另一个值。模型名称本身不代表真实权限，未测试也可保存草稿。

「测试连接」单独操作，说明将使用当前草稿（包括本次明确替换的凭证）、目标供应商/模型和极短测试输入，可能产生少量用量。保存、打开详情、启用、设默认不得自动发送推理探测。测试结果区分：未测试、成功、鉴权失败、模型不可用、超时/网络错误、配置错误，记录时间和已测试草稿 revision；草稿变化后标记“配置已变更，测试结果可能过期”，不显示为当前已验证。

「设为默认」仅允许已启用且配置完整资源，弹出影响列表；默认模型停用可以执行但必须明确所有默认引用 Agent 会不可用，不能自动切到另一家供应商。系统无可用默认时给可读错误，已固定其他模型的 Agent 不受影响。迁移现有配置时默认关联当前 Kimi；OpenAI 可保存未启用、未测试，不自动调用。

### 凭证编辑（适用于模型、HTTP、MCP）

统一显示「未配置 / 已加密保存 / 引用服务端变量：变量名」，不显示原文、尾号或可用于恢复的片段。输入区域有三种明确操作：

1. **保留当前**（默认）：密码输入留空表示不改动；切换页面、保存其他字段不清除凭证。空白不能自动覆盖已保存值。
2. **替换**：选择「输入新凭证」或「引用服务端变量」。前者用密码控件，不支持从服务端回显；后者填写管理员允许的服务端变量名，只验证是否配置，不返回值。替换缺少新值时阻止保存，不退回隐式保留。选择另一认证模式也必须显式确认替换操作。
3. **清除**：展示“当前引用者可能无法连接”，明确点击清除后写入草稿；仅保存草稿不立即影响已发布凭证，发布前展示清除差异。仍要求认证的资源缺少凭证时不能启用；用户可显式切为无认证（仅该类型支持时）再发布。

新输入值不写 URL、浏览器持久化存储、返回响应、日志或导出；提交成功/取消后清空本地密码控件。服务端加密保存，独立解密主密钥不与数据库同存；主密钥缺失时阻止保存原文凭证并给运维配置说明，仍可使用已有服务端变量引用，不降级明文。凭证从已发布配置中继承时不能由于草稿清除而提前失效；具体密钥轮换格式由架构明确。

## 5. 工具页面（RC04、RC05、RC09）

统一列表支持来源「内置 / HTTP / MCP」、读/写、状态、搜索和引用筛选。详情展示输入 Schema、认证是否配置、执行规则、版本及脱敏最近调用。MCP 定义跳转到对应服务同步详情，不可在此改协议 schema。内置工具代码实现、稳定身份和基础风险不能编辑，只能改展示信息、全局启停及更严格规则。

### HTTP 工具表单与执行

字段：名称、简介、稳定标识、GET/POST/PUT/PATCH/DELETE、固定服务 URL、输入 JSON Schema、参数映射、认证、超时、响应提取、读/写属性与确认规则。第一版支持 JSON 数据，不接受任意 JS/Python/SQL。

参数映射使用行编辑器：参数来源（输入字段路径/固定字面量）→ 目标位置（路径/查询/Header/JSON Body）→ 目标字段。来源路径采用明确约定（例如 `customer.id`、`items[0].id`），支持对象/数组原值传递。路径参数逐段编码；查询参数编码；JSON Body 按类型组装，不用字符串拼接用户输入形成原始请求。Header 名称和值需有效，业务输入禁止覆盖 Authorization、配置的 API Key Header、Host、Cookie 或连接目标/超时/执行规则。GET 不发送 body，缺失必填映射失败且不外呼。URL 主机、端口、scheme 固定，模型只能填写 schema 允许业务参数；未知输入字段处理规则必须在 schema 明确（默认拒绝额外字段）。

认证至少无认证、Bearer、API Key Header；API Key Header 名可配置但不能来自调用输入，凭证遵循上节。GET 可选只读；POST/PUT/PATCH/DELETE 默认写入，管理员将确实无副作用的 POST 查询标为只读时须显式声明并在发布差异突出显示；已有内置基础写风险不可降级。所有写工具本轮**强制确认**，只能将更多只读工具纳入需确认，不能关闭写确认。

响应提取支持 `$` 整体、点路径和数组索引（例 `data.items[0].name`）；返回对象、数组、字符串、数字、布尔或 null。路径不存在报“响应提取失败：字段缺失”，JSON null 是有效结果；不把缺失当成功空串。Schema/映射/字段路径的最终语法由详细设计统一公开，原型语法为上述基准。

执行区分参数/映射错误、目标未授权、HTTP非2xx、超时、非JSON、提取失败、响应过大。展示经过脱敏的摘要和耗时，不原样回显服务端错误体。默认响应上限 1 MiB、传给模型工具结果上限 32 KiB，超限明确失败或显示截断标记；写请求已经发送时错误文案应为“结果未确认，请核实业务系统，系统不会自动重试”，不能声称一定未执行。写请求一律不自动重试，读请求第一版也不自动重试，简化次数和用量语义。

目标授权作为管理员配置单独展示「允许的 scheme/host/port 与本地/内网许可」。仅 HTTP(S)，禁止 URL 用户信息、云元数据及保留端点、DNS 重绑定绕过和跨域重定向携带凭证；自有回环/内网服务允许以精确目标显式授权，不允许整个任意私网段的默认放开。每次实际连接验证解析目标，具体地址规则由架构设计和负向测试给出。连接异常不得改用其他目标。

### 工具测试

填写测试参数后先做本地/服务端参数检查，展示工具版本、方法、脱敏 URL/映射预览、输入和预计副作用。只读点击「执行测试」；写工具或额外需确认工具先显示「等待确认」，用户再确认具体动作才执行。测试不走免确认捷径。默认测试已发布版本；选择草稿测试时明显标记 revision，使用同一解析、授权、确认、预算、超时和审计执行器。

## 6. MCP 页面（RC06、RC07）

列表显示服务名称、传输类型、地址、发布状态、连接状态、工具数量、最近同步结果及引用数。详情可编辑名称、简介、地址、认证、超时、目标授权。传输选择「标准 MCP · Streamable HTTP」「项目 HTTP 桥 · 兼容」，两者文案/图标明确分开，不支持 stdio/本地命令或安装软件。

标准类型必须完成协议初始化、发现和工具调用及必要会话/错误处理。支持的协议版本及认证边界由架构依据官方规范写明，不可用旧桥伪装标准协议。连接测试与工具同步分别展示成功/认证失败/超时/协议不兼容状态。

「同步工具」得到**候选目录**，逐项分组为新增、变更、移除、无变化；展示原始名称、schema、描述、风险和已授权引用。新增工具未被任何 Agent 自动授权；未知风险默认写入/需确认。同步成功不直接发布，点击「发布同步目录」经差异影响确认后原子生效。同步失败保留当前已发布目录、上次成功时间和错误；不能清空列表造成错误下线。

成功发现的移除项在待发布期间标为“待发布移除”；发布后新执行拒绝，已开始任务也不得开始调用当前已移除工具。若上游已先移除，旧目录调用返回明确工具不可用错误，不换服务、不误报成功。变更 schema 发布后新任务使用新 schema；待确认动作遇版本变化必须重新发起。管理员对风险作经核实调整时纳入发布差异，绝不能自动把未知风险认定只读。

Agent 关联 MCP 时先选已启用服务，再逐一勾选其**已发布**工具，保存精确身份。关联服务本身不授权所有工具，空勾选即不允许该服务工具；未来新增工具需人工选择并重新发布 Agent。多个服务存在同名 `search` 时各自独立映射、授权、审计。

## 7. 技能页面（RC08）

技能支持新建/编辑草稿、发布、启停、版本详情、引用和删除约束；保留并迁移清晰表达、订单查询、知识检索技能。字段包括名称、简介、指令、适用主/子类型、依赖工具（统一目录，含HTTP/MCP）、知识检索开关、使用说明。

依赖可视化按来源分组展示读/写和所属 MCP 服务。选择写依赖后只能适用子 Agent；主 Agent 不可借技能执行写。启用/发布验证完整依赖链，错误定位至具体工具或服务并提供跳转。运行时技能指令追加，工具与直接授权合并去重，知识检索按能力开关执行。

技能 v2 发布后，绑定 v1 的 Agent 保持原指令和依赖集；Agent 显示当前 v1、可更新 v2。「查看更新」并列展示指令和依赖差异，特别突出新增写能力；接受更新仅修改 Agent 草稿，重新发布时再校验权限与完整依赖。技能普通停用阻止该技能所有版本的新使用；某依赖工具被全局停用亦不允许旧版绕过。

技能回滚选择历史快照形成新的发布版本，不回写旧版；引用者仍需显式升级。技能不提供可执行脚本和安装入口。

## 8. Agent 页面与运行规则（RC03、RC08–RC12）

编辑结构：「基本信息」「提示词」「模型与能力」「子 Agent（仅主）」「运行规则」「发布与试运行」。创建可一次填写必要字段，保留上一轮完整创建/启用体验；高级内容可分区，不要求用户编辑 JSON 才能完成关联。

「模型与能力」包含已启用模型下拉（系统默认、资源名称/供应商/模型）、继承参数及有效值、统一工具选择、技能版本选择、MCP精确授权和知识检索。旁边展示“实际能力汇总”：模型来源、技能绑定版本、合并工具身份/来源/读写/确认要求及检索方式，不把知识检索放在运行规则中。

运行规则使用以下准确标签和语义：

| 页面字段 | V1规则 | 默认/边界 |
| --- | --- | --- |
| 允许修改业务数据 | 子 Agent 开关；关闭则全部写工具不可执行，即使技能/MCP引入也不得执行 | 默认关闭；主 Agent 固定关闭 |
| 需要用户确认的工具 | 所有写工具固定选中不可取消，可对只读工具追加确认 | 确认始终在实际执行前发生 |
| 最多工具调用轮数 | 按下述模型工具批次计数，主/子分别计数 | 默认3，可0–20；0即禁止任何工具执行 |
| 单工具超时 | 每次工具执行等待上限，统一覆盖内置/HTTP/MCP | 默认30秒，可1–300秒，实际取资源超时和剩余总时长的更小值 |
| 单任务总超时 | 当前 Agent 处理模型及工具的累计活跃耗时 | 默认120秒，可1–600秒；子不得超过主剩余总时间 |
| 最多子 Agent 转交 | **本轮最多1次，固定只读**；仅主 Agent 显示 | 不提供0/2等无效数字；第二次转交、子→子或子→主执行请求拒绝并提示 |
| 注入会话摘要 | 控制是否将当前会话公开摘要加入该 Agent 的模型上下文 | 默认开启 |
| 保留历史对话轮数 | 只控制当前 Agent 输入上下文中的已完成公开对话轮数 | 默认10，可0–50；当前用户输入不计历史且只注入一次 |

### 8.1 轮数、预算和超时

一次模型响应中包含一个或多个工具调用要求，算**一轮**。同一批次三个工具是1轮而不是3轮，但审计记录3次独立调用；再次请求模型又返回工具批次才进入下一轮。没有工具要求的纯文本响应不计工具轮数。批次在执行第一项前检查/预占一轮预算；任何工具失败或等待确认都不退还已占轮次。无权限/非法schema等请求拒绝后终止该批次，不用失败自动循环来消耗无限模型请求。

第一版同批工具按模型返回顺序执行，便于统一确认和去重；允许未来受控并行但不改变计数。默认最多每批10项工具调用，超过整批拒绝且不执行，避免单轮无限量工具。若一批包含多个需确认工具，可一次展示整批动作清单，但确认必须绑定每项身份/参数/版本；未完成确认前不得执行其中需确认项。先前已完成只读项不因确认恢复重复执行。

主/子分别遵守自己的轮数上限；转交仅一次，不能通过往返重置上限。根任务同时持有总截止预算；子有效总预算取“子设置”和“主剩余预算”较小值。每次模型调用、工具执行和转交前检查剩余时间；请求超时取模型/工具资源配置、Agent单工具设置（工具时）、剩余总时长的最小值。达到上限后停止后续动作，返回“达到工具轮数上限/单工具超时/任务总超时”等准确原因，并记录轨迹。

等待用户确认期间不计活跃执行耗时；暂停时保存剩余预算、已使用轮数及工具批次进度。恢复同一待确认任务不能重置轮数/总预算，已执行项不能重复；待确认有效期30分钟，过期必须重新发起。超时或取消不意味着已发出的外部写入被撤销，需给明确提示。

### 8.2 统一确认

统一执行器在实际执行前拦截内置、HTTP、MCP三类写动作及额外需确认只读动作，正式聊天、试运行、工具测试同规则；不得再只识别“取消订单”文本。

确认卡显示工具中文名/来源、Agent、业务参数、动作影响、关联资源版本和确认有效期，凭证/敏感Header永不展示。服务端保存不可伪造动作ID、工具稳定身份、参数、Agent/资源版本、权限快照、当前轮次和剩余预算；浏览器只提交动作ID及确认/取消，不把浏览器回传参数作为执行依据。

确认时重新验证当前 Agent、模型/技能/工具/MCP 状态、权限和版本。**相关 Agent或资源发布版本变化即使仍启用，也拒绝旧确认并提示重新发起**，不能用新配置执行旧参数或用旧权限绕过新设置。一次确认只能执行一次，重复/并发确认返回已处理结果或冲突，不再次外呼；取消/过期也不可重新执行。工具写请求不自动重试。

### 8.3 跨 Agent 记忆

同一个会话共享**用户可见的公开历史**：用户输入和最终展示给用户的助手回复。主 Agent 与 Worker 均可在各自历史轮数范围读取这部分历史；不共享其他 Agent 的系统提示、思考、隐藏工具参数/结果和私有工作消息。内部主路由消息不算公开回复；内部转交不产生额外历史轮。

一轮历史是一个已完成的“用户输入＋最终公开回复”对，按最近N轮选取，保持顺序；当前用户输入单独加入且不重复。N=0时不注入历史对，摘要开启仍可单独注入摘要。摘要仅概括本会话公开内容，不得混入隐藏工具原文；关闭摘要后不发送摘要。跨会话/用户严格隔离。切换页面主 Agent 继续沿用既有创建新会话行为，不把旧会话历史自动带入新会话。

工具确认恢复使用同一任务已捕获上下文，不因新的其他会话消息扩大历史；跨 Agent 只共享受授权公开历史和当前任务必要转交信息，不将Worker内部执行缓存作为公开历史暴露。

### 8.4 试运行与正式诊断

两者使用同一资源解析、工具授权/确认、预算和记忆逻辑。试运行清楚显示草稿/发布版本，不以试运行绕过权限。全链路模式使用已发布主 Agent；单 Agent 草稿测试需固定其revision和资源快照。

结果展示实际 Agent/发布或草稿版本、模型资源名/版本、供应商/模型标识、工具逐项轨迹（名称/来源/版本、脱敏参数摘要、状态、耗时、是否等待确认、错误）、工具轮数/剩余预算及结果。状态至少请求、待确认、执行中、成功、失败、取消/拒绝/超时；无工具执行明确“本轮未调用工具”，不能对真实执行返回空汇总。正常JSON和现有SSE均返回一致最终诊断；Kimi注明缓冲输出，不声称上游逐token。

## 9. 迁移、回退和异常恢复（RC11、RC13）

现有 Agent/技能/工具映射成稳定资源，不改变旧code；保留旧草稿、发布版本和已有模型使用能力。原配置没有模型引用时继承系统默认；从服务端环境变量引用现有 Kimi/OpenAI 凭证，不把真实值复制进种子/日志/迁移文件。旧“策略”字段映射为实际运行规则，无法兼容的值明确报告并采用有依据默认，不能静默丢失用户内容。

迁移必须可重复执行，提供升级前备份、迁移结果、失败回退和新版数据降级限制；在独立旧数据副本上验证。真实进程重启验证当前已发布资源、技能版本绑定、Agent引用、默认模型及凭证状态恢复；草稿不进入运行。待确认状态若持久化恢复必须保留幂等及预算，若不可安全恢复则明确失效而不是重复执行。

普通资源读取不能触发连接/推理外呼；模型/MCP失败不自动跨提供方/服务回落。服务端独立解密密钥缺失时相关凭证不可用，界面准确说明，不能回退其他密钥。

## 11. 原型与交接

原型用内存演示数据覆盖五页面和资源详情、草稿发布影响、凭证操作、MCP同步差异、技能升级、Agent规则以及统一写确认/轨迹。标记为“演示，不连接业务系统”，不会读写8080、凭证或外部服务。原型用于设计沟通，不是功能实现或协议验证证据。

以下决策在本次交接后作为实现契约：每个模型工具批次计一轮；最多1次单层转交固定展示；共享同会话公开历史、各Agent分别裁剪；任务开始固定资源版本但停用优先；技能显式版本升级；确认遇相关版本变化重新发起、预算不重置；凭证保留/替换/清除明确区分；MCP同步产生待发布目录并由发布操作生效。实质调整须先由项目经理/根协调同步并更新本PRD，不由角色各自解释产生互斥实现。
