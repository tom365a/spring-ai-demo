# 统一资源配置项目计划

日期：2026-09-10 起，2026-09-11 结项。负责人：项目经理 Agent。正式接收 [REQUIREMENTS_SCOPE.md](REQUIREMENTS_SCOPE.md) V1.0 的全部范围及 RC01–RC15，已全部交付并取得证据。既有两个迭代结项保留为历史记录。

## 1. 交付目标与实施原则

五个一级页面管理 Agents、模型、工具、MCP 和技能；配置必须实际影响执行。包括同进程每 Agent 模型路由、内置/自定义 HTTP/标准 MCP Streamable HTTP 与旧桥分类、技能显式版本绑定、三类工具统一确认与执行预算、Agent 记忆、工具轨迹、资源草稿发布与引用/迁移。REQUIREMENTS_SCOPE 是范围基线，不因工时或难度擅自删减。

保持 8080 用户应用运行。开发与独立测试使用独立端口、H2 数据库和上传目录，测试资源不得混入用户应用。真实 Key 只在根 .env，由根协调 Agent 管理；其他角色不得读取、复制或输出。OpenAI 仅本地模拟协议；极少量真实 Kimi 最终验收由根协调 Agent 执行。Kimi 仍是缓冲式 SSE，不宣称上游 token streaming。

### 开发切片与并行边界

R1交接后架构师确认：A资源实体/版本/加密凭证/依赖迁移 → B请求快照与统一工具确认/预算/轨迹 → C每Agent模型与HTTP/MCP适配 → D技能版本/记忆/Agent接入 → E五页与发布影响交互 → F迁移重启/自测。首个实施点是ResourceDefinition、Resource/Version/Credential实体与事务生命周期，在模型/工具接入前以合成凭证及草稿隔离测试建立基础。

最终并行分工已确认：根协调承担独立HTTP/MCP传输模块（由架构师给定接口与独占目录）；架构师负责数据库/凭证/快照/统一执行及Agent主集成；架构师在统一API契约后调度前端实现协作者负责E五页与admin-app，QA保持独立。PM结束等待turn释放第4槽给前端，候选/阶段调度时唤醒继续R4–R6，不代表项目完成。
