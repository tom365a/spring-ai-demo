# 统一资源配置独立测试计划

版本：0.2（已对齐产品PRD 1.0）；日期：2026-09-10；负责人：测试工程师 Agent。

依据：[REQUIREMENTS_SCOPE.md](REQUIREMENTS_SCOPE.md) V1.0、[PROJECT_PLAN.md](PROJECT_PLAN.md)、[PRD.md](PRD.md) 1.0。已纳入产品确定的预算、记忆、确认和MCP候选发布语义；API和协议版本等待架构详细设计补充。**当前只完成测试设计，所有场景均未执行，无通过结论。**

## 1. 职责、环境与执行门禁

- 独立 QA 只使用项目自有合成数据、合成凭证、独立测试端口/数据库/上传目录；不读取 `.env`，不访问或修改用户正在运行的 8080 应用。测试进程由 QA 创建并仅清理自己创建的进程。
- OpenAI 全部使用本地兼容服务；模型测试上下文移除宿主环境变量来源，再注入合成密钥与 loopback 地址，防止继承真实凭证。不得通过探测真实 OpenAI 付费接口检查可用性。
- 真实 Kimi RC14 由根协调 Agent 独占执行。QA 提供最小验收场景并审核脱敏证据；未收到实际证据前标记“待根协调执行”，不将离线替身通过换算成在线通过。
- 正式 R4 测试需架构师提交候选、自测结果、接口/协议契约、迁移与回退说明。提前可制作测试服务和用例，但不得提前签署业务验收。修改业务文件或架构师测试均回派架构师。
- 建议应用端口 18080，模型/业务 HTTP/MCP 服务使用 OS 分配的随机 loopback 端口；实际执行前检查占用，只启动自己管理的服务。数据路径采用独立 `target/resource-qa-*`，不复用此前页面验收库或用户库。
- 候选以实际文件状态和编译完成时间标识，不虚构 Git 提交。每次修复登记影响范围，复测针对失败项和必要回归；最终证据不能引用已被后续变更推翻的早期结果。

证据分为：`U` 自动化业务/组件；`I` 真实 Spring/JPA 集成；`W` 自有服务捕获的实际 HTTP/JSON/SSE 协议；`B` 浏览器真实操作；`M` 独立旧格式数据迁移与实际 JVM 重启；`K` 根协调真实 Kimi。不同来源分别记录，不以 API 脚本冒充页面、不以旧桥冒充标准 MCP、不以缓冲 SSE 冒充 Kimi 上游逐 token 输出。

## 3. 高风险专项展开

### 3.1 凭证隔离和加密（RC02/03/11）

使用不同、可搜索的合成明文标记作为模型、HTTP、MCP三类凭证及独立主密钥。对自己创建的测试库、版本快照、接口响应、连接错误、审计、导出和日志进行检查：不能包含这些明文。必须验证密文可以在仅提供正确外部主密钥时恢复使用；缺密钥、错密钥、篡改密文均不得降级为明文或使用另一Provider凭证。验证解密主密钥不与密文同库。

页面空凭证保留、替换、明确清除分别测试；仅有掩码不能视为已完成加密。环境变量引用只引用QA注入的合成变量，不允许测试代码枚举或读取真实宿主秘密。并发两个模型/工具连接时检查其Authorization及认证Header分别正确，不能依赖进程全局可变key。

### 3.2 三类工具的统一确认与抗重复（RC09）

每种工具来源都覆盖三个入口：正式聊天、Agent试运行、工具测试。所有写工具及管理员要求确认的只读工具，在执行边界拦截；确认前内部执行计数和自有服务请求计数均为0。测试不能只发送包含“取消订单”的文字，应让受控模型直接生成写ToolCall，证明拦截不依赖关键词。

| 入口 | 内置写工具 | HTTP写工具 | MCP写工具 |
| --- | --- | --- | --- |
| 正式聊天 | RC09.1：服务端待确认→显式确认→实现执行仅1次 | RC09.2：确认前HTTP次数0，确认后仅1次 | RC09.3：确认前tools/call次数0，确认后仅1次 |
| Agent试运行 | RC09.4：草稿/发布选择不旁路确认或Agent写权限 | RC09.5：同正式执行器与预算，成功后真实工具轨迹 | RC09.6：精确工具白名单与未知风险默认写确认 |
| 工具测试 | RC09.7：操作角色与执行确认都检查，不能直接调用实现 | RC09.8：预览脱敏方法/参数，publisher确认后仅1次 | RC09.9：固定服务及已选工具身份，不能借测试调用未授权项 |

九个单元都需正常确认、取消、客户端参数篡改和重复/并发确认验证；三种来源还各自覆盖停用、相关版本变化、过期及超时后重复确认。写工具确认不可关闭，额外只读确认至少用一种来源验证。前置操作权限依PRD执行：viewer只读，editor安全只读试运行/连接测试/同步候选；publisher/admin负责凭证变更、目标授权、启停发布及适用的写测试权限。

至少覆盖：正常确认、拒绝、过期、已完成重放、两线程同时确认、修改客户端参数/工具ID/资源版本/确认ID、跨会话提交、停用后确认、收紧权限后确认、发布新资源版本后旧确认。PRD已经固定：浏览器只提交动作ID和确认/取消，相关Agent或资源版本变化即拒绝旧确认，必须重新发起；有效期30分钟，使用可控时钟验证边界，不实际等待30分钟。确认恢复保留剩余活跃预算、已占工具轮数及批次进度，先前已完成只读项不重做。对发生超时但服务已收到的写请求，不得因重试确认自动重复外部操作；需记录可恢复的明确状态。

混合工具一轮既有读取又有写入时，按PRD明确的执行顺序和确认语义测试，不允许因读工具成功把写工具视为已授权。需要检验工具回调直接路径、MCP调用路径与HTTP测试路径共同遵守同一规则。

### 3.3 HTTP目标与响应控制（RC04/05）

自有服务提供请求捕获、嵌套/数组JSON、错误状态、非JSON、延迟、分块大响应、重定向和模拟“已处理后断连”响应。请求映射验证URL保留字符、JSON字符串转义、缺少字段/错误类型、Header大小写及认证Header保护；模型输入不得覆盖协议、host、port、base URL或执行预算。

目标约束用合成字符串与可替换DNS解析验证：非HTTP(S)、用户信息URL、保留/元数据地址、IPv4/IPv6及其等价表示、域名解析为受禁地址、重定向和DNS变化。禁止真正对云元数据或第三方内网发请求。明确授权的loopback测试目标必须可用，不能把所有本地目标禁用后宣称满足项目需求。

响应上限同时覆盖Content-Length已知及分块未知长度，断言实际读取停止且结果截断/拒绝行为符合设计；响应字段提取后的结果长度也受限。写工具失败/超时的服务请求数必须为1；不得由HTTP客户端或模型适配器隐藏重试造成重复业务操作。

### 3.4 标准MCP与旧桥分离（RC06/07）

标准测试服务按架构声明支持的MCP版本实现JSON-RPC初始化、initialized通知、tools/list、tools/call、会话ID和HTTP错误；不复用旧 `/tools`、`/tools/call` 响应冒充标准协议。固定协议版本及必需请求头需在R2交接后填入，不在此预设未核实的值。

两标准服务各提供同名工具但返回不同服务标记，检查模型名称映射和授权白名单。同步只产生候选目录，校验新增/变更/移除差异；没有执行“发布同步目录”前线上不变。发布后新增工具仍未自动授权，已移除项不允许新执行，schema变化使旧确认失效。同步异常前后比较已发布目录和版本，保留原版本且标记失败。另启动旧桥服务，独立记录其兼容类型、旧路径和回归结果。

### 3.5 发布、技能授权与在途请求（RC08/11）

使用并发屏障暂停模型/工具调用：请求A读到资源v1后发布v2，请求A仍固定其允许继续使用的配置快照，请求B使用v2；若全局停用，则A尚未发出的新工具执行也必须重新检查并拒绝。已发出的外部请求不能承诺撤销，审计需反映实际结果。

技能v1只授予读工具，v2新增写工具；旧Agent运行版必须继续v1。显式升级先生成Agent草稿，只有发布Agent后新能力才可能进入允许集合，且仍需写权限与确认。检查资源重命名不改变稳定引用，删除引用资源被阻止，依赖失效的错误准确定位。

### 3.6 旧数据迁移、重启与回退（RC03/11/13）

使用独立旧格式合成数据库，覆盖：已启用发布版、不同内容的未发布草稿、已停用Agent、主子关系、无新资源ID的旧模型字段、旧内置技能列表、历史版本及本地知识文件。不得复制或修改用户8080运行数据库。

升级前记录表行数、稳定ID和各业务快照；执行迁移两次验证幂等；真正终止QA JVM后以同一文件库启动新JVM，再验证已发布恢复、草稿隔离、引用与技能版本保持、默认模型使用服务端凭证引用而非复制明文。按迁移说明执行测试副本回退并核对旧数据；不把单次Registry重载称为进程重启，不把仅能新建数据库称为旧库迁移通过。

## 4. 已确定的PRD细则及架构交接待办

以下已按PRD 1.0固定，正式测试不得自行更改含义：

- **RC10.1**：工具轮数默认3，合法0–20；同模型响应内多工具计1轮、按返回顺序执行，第一项前预占轮次；批次失败/待确认不返还轮次；超过10项整批拒绝且执行次数0。至少断言1批3项为1轮3条轨迹、11项为0次执行、0轮配置不执行、确认恢复不重置。主子各自计轮，最多一次转交。
- **RC10.2**：单工具默认30秒、1–300秒；Agent任务默认120秒、1–600秒。实际超时取资源配置、Agent限制和根任务剩余时间的最小值；子预算不超过主剩余。确认等待不计活跃耗时，但保留剩余额度与30分钟有效期。用可控时间/短延迟边界，不靠长时间睡眠凑证据。
- **RC10.3**：历史默认10轮、合法0–50；一轮是已完成用户输入与最终公开回复对。当前输入只出现一次且不算历史。主子共享同会话公开历史，各自裁剪；不共享系统提示、思考或隐藏工具参数/结果。摘要单独控制，N=0且摘要开可只注入摘要；跨用户/会话隔离；确认恢复使用原任务上下文。
- **RC02.2**：凭证状态不显示尾号；替换无新值拒绝，空白默认保留；清除写入草稿，不提前影响已发布凭证；缺主密钥拒绝保存原文但可用合法环境引用。成功/取消清空密码控件，不存浏览器持久化存储。连接测试对应草稿revision，草稿变化后结果过期；保存/启用/默认切换都不探测推理。
- **RC04/05**：GET不带body，映射用结构化原值保留类型；提取`$`、点路径及数组索引，JSON null有效、路径缺失失败；响应默认1 MiB、模型结果32 KiB。所有HTTP读/写第一版均不自动重试；已发出写请求的不确定结果不得宣称未执行。只可加严内置风险，所有写工具强制确认。
- **RC08/11**：资源删除检查所有Agent/技能草稿和当前发布引用；历史版本保留不可执行墓碑，回滚遇已删依赖失败。技能停用影响全部旧版本；技能回滚形成新版本不重写旧版。任务开始固定主子及全部资源快照，每次新模型调用/工具/转交复查全局停用；停用优先于快照。

架构交接仍需提供以下实现可测点，不向用户重复询问已授权范围：

1. **预算与记忆**：上述PRD语义对应的可控时钟、批次/预算持久化和模型上下文捕获方式；超时后的后台请求与审计处理。
2. **确认**：动作ID/会话绑定、原子领取状态机、外部已接收但本地超时的恢复契约；三个入口共用的具体执行API。
3. **发布**：影响确认契约、资源快照格式与停用复检点，提交失败注入点和并发冲突响应。
4. **HTTP**：目标授权形式、DNS与重定向策略、映射语法/JSON路径规则、Schema支持子集、响应字节/字符上限及错误码。
5. **MCP**：声明协议版本、初始化与会话生命周期、JSON/SSE响应支持、分页工具发现、鉴权方式、同名映射及同步变更发布规则。
6. **迁移**：旧schema/数据格式、新资源和凭证引用生成规则、主密钥来源、可重复执行及回退要求。
7. **页面验收**：产品负责的真实页面任务清单、根协调页面/真实Kimi证据交付方式，以及最终候选版本定位方式。

## 5. 执行顺序、缺陷和报告门禁

R4顺序：候选自测/设计审查 → 凭证与数据隔离冒烟 → 模型资源/协议 → 三类工具统一执行与确认 → 技能/规则/记忆 → 发布竞态/迁移重启 → API与浏览器回归 → 缺陷复测。通过核心离线门禁后才移交根协调做RC14极少量真实调用与产品验收。

缺陷记录必须包括RC编号、候选时间、步骤/请求、预期/实际、影响、脱敏证据、负责人、修复与复测结果。沿用项目计划：P0包括凭证泄漏、未授权写执行和严重数据破坏；P1包括配置不生效、资源串用、确认/预算绕过、隐式OpenAI外呼、迁移丢数据、原子发布破坏和关键流程不可用。未关闭P0/P1禁止通过；不得把必需范围改标为后续项。

最终TEST_REPORT为每个RC列出测试名称/命令、执行环境、实际证据链接、通过/失败/未执行/受限及原因。浏览器、真实MCP、旧桥、离线模型、真实Kimi证据分列。RC14未执行或关键证据缺失时不签全范围通过；QA完成后产品验收和PM结项仍需依次执行。
