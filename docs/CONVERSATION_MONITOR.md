# 客服会话监控

## 会话边界

打开客服聊天页面立即创建一个会话，创建时间作为尚未输入时的活跃起点。用户输入文字、提交消息或上传图片更新最后输入时间；连续 5 分钟没有用户输入时结束。助手回复、模型执行、监控查看及人工评价不能延长会话。页面切后台、关闭或网络断开时，后端仍负责按最后接收到的输入时间结束会话。

结束后再次输入创建新的会话 ID。每个会话可以包含多轮主 Agent 识别、子 Agent 处理与工具调用。手动新建会话会先结束原会话。计时以服务端收到活动为准，页面输入事件节流上报，并在输入结束后补报；不会在用户无输入时发送保活心跳。

## 监控页面

入口 `/admin.html#/monitor`，支持搜索会话和用户、按解决状态筛选、分页、刷新。详情按时间串联公开用户/助手消息与已记录的执行事件，展示任务身份、实际路由和工具轨迹；试运行和正式会话通过渠道区别。

“会话结束”和“问题已解决”分别记录。自动超时结束不会假定已解决。解决状态为待解决/待确认、已解决、未解决，管理员核对对话后填写判定依据，历史评价保留。会话仍进行时，如果用户再次发送问题，已有判定重新进入待确认，避免后续未处理的问题被旧评价覆盖。

不把内部推理当作客服日志展示，不补造旧会话缺失的主子转交记录。已有历史会话展示已保存消息，新事件从本模块上线后记录。现有 Demo Header 角色仍用于页面权限区分，不能视为生产身份认证。

## 验证

前端可控时钟测试：`node scripts/test-session-idle.mjs`，覆盖打开即创建、5 分钟边界、输入重置计时、超时新会话、并发创建合并与手动关闭。

后端 `ConversationMonitorTest`、`ResourceRuntimeSelfTest`、`HumanSupportTest` 共 16 项通过，覆盖超时关闭不等于解决、输入活跃与助手消息分离、评价重置、旧历史可读、实际主子路由与工具事件、结束会话不能确认、模拟坐席分配与故障提示。整机 `node scripts/check-monitor-support.mjs` 验证隔离后端和本地协议服务的真实 API，证据在 `docs/monitor-evidence/integration.json`。

浏览器已验证监控列表、完整多轮时间线、角色切换后编辑权限、人工未解决判定保存，以及无匹配业务→点击转人工→同一会话由模拟客服继续回复。

## 转人工与 IM 模拟

新增 `human_support_1`、`human_support_2` 两个 WORKER Agent，界面及回复明确为 AI 模拟人工坐席，不是真人服务。它们不作为普通业务路由候选；用户点击转人工按钮后，服务端在已启用坐席中按当前未结束会话数选择负载较少者。分配以 sessionId 持久化，重复转接幂等，直到会话结束后才创建新的分配。

异常、超时、没有匹配能力时输出 `diagnostics.handoffAvailable` 和提示。普通澄清不会自动视作无业务能力。转人工需要用户点击，转接后清除原待确认状态，原确认不能继续执行；已经发出的外部写请求不能保证撤销。模拟坐席接收同一会话已有公开文字历史，不接收模型内部推理，也没有自动执行业务写工具权限。模拟回复服务同样不可用时明确告知并保留消息，不伪称真人已处理或问题已解决。

`SupportImAdapter` 隔离回复能力；当前实现为 `SimulatedSupportAdapter`。实际平台还需要根据所选 IM 的认证、坐席在线状态、排队、消息回调、附件及送达确认协议另行接入，本轮没有冒称已连接外部 IM。当前模拟坐席只消费公开文字，图片消息的附件记录保留，图片理解不属于该模拟适配器。

API：`POST /api/v1/sessions/{id}/handoff` 接收 `{userId}`，返回分配坐席和 `mode=SIMULATED`；`GET` 同路径带 userId 查询。转接后的普通 `/chat` 与 `/chat/stream` 自动路由至已分配坐席。监控记录 HUMAN_ASSIGNED、HUMAN_MESSAGE、HUMAN_REPLY / HUMAN_REPLY_FAILED 事件。

当前列表分页及坐席负载汇总在内存完成，适用于本地 Demo；大规模日志应改用数据库筛选聚合、索引和归档。超时扫描仅查询到期且未结束会话再加锁复验，不每秒锁定全部历史会话。
