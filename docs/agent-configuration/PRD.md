# Agent 页面配置产品需求

版本：1.0；日期：2026-09-10；责任人：产品 Agent。前置：[项目计划](PROJECT_PLAN.md) S0 已完成。本文件用于 S1 产品交接，验收状态尚未开始。

## 1. 用户目标与范围

使用者进入 Agent 管理页，一次填写名称、简介、提示词，选择可使用的工具和技能；选择“主 Agent”时关联已启用子 Agent。点击“创建”保存为未启用草稿，确认后点击“启用”，后端自动校验、形成发布版本并加载，之后可以从正式聊天页面使用，无需重启或手工修改数据库。

沿用当前 Spring Boot + 静态管理页，在现有 Agent 管理与客服对话基础上补齐配置闭环。本轮项目经理、产品、全栈架构师、测试工程师是项目交付协作角色；不增加项目流程引擎、任务管理产品或创建四个演示业务 Agent 充当交付结果。

不包含技能上传、任意代码执行、外部技能市场、完整账号登录/SSO、多租户、删除已发布 Agent、新一代前端框架。现有模型/MCP/版本/回滚/试运行保留可用。现有演示管理角色机制不是生产身份认证。

## 3. 名词与状态

- 主 Agent（SUPERVISOR）：接收正式聊天请求，依据提示词和子 Agent 简介分发；本期只能关联子 Agent。
- 子 Agent（WORKER）：执行专门任务，可配置提示词、工具和技能，不可关联任何其他 Agent。
- 工具：后端已注册的可信能力，例如“查询订单”“查询物流”；勾选决定可调用范围。具有写副作用的工具沿用现有确认机制。
- 技能：本项目内置、可复用的能力包，包括提示指令，以及明确的工具依赖或知识检索能力。不是运行 Codex 的本机 SKILL.md；目录项名称、说明、适用类型及依赖在页面可见。
- 草稿：可编辑的未生效配置；已存在运行版本时，修改草稿不会替换运行版本。
- 已启用：存在有效已发布版本，后端已成功加载且配置聊天入口可达；不能只依赖 enabled=true 显示成功。
- 已停用：保留配置和历史，停止调度；重新启用需要验证有效配置与依赖。

状态路径：新建 → 未启用草稿 → 启用中 → 已启用；校验或持久化失败返回明确错误并保留原状态。已启用 → 编辑/保存草稿 → 显示“有未生效修改” → 发布更新 → 新版本生效。已启用 → 停用 → 已停用 → 启用 → 已启用。

## 4. 页面与交互

设计参考为 [PROTOTYPE.html](PROTOTYPE.html)，原型使用演示数据说明布局/交互，不连接业务 API，不作为功能测试证据。实际实现沿用当前深色青绿风格，桌面双列、窄屏单列，弹窗内部可滚动，提交按钮可触达。

### 4.1 列表

提供名称/标识搜索、类型/状态筛选和“创建 Agent”。每行包含名称、简介、类型、运行状态、当前发布版本、编辑/试运行以及启用或停用按钮。未发布草稿显示“未启用”，已发布但停用显示“已停用”，不能展示误导的运行成功状态。网络请求期间按钮禁用，成功后刷新服务端状态。

### 4.2 创建

| 字段 | 规则 | 提示/默认 |
| --- | --- | --- |
| 名称 | 必填，去除首尾空白，不接受空白串 | 如“售后咨询助手” |
| 标识 code | 唯一；兼容已有 `^[a-z][a-z0-9_]{1,63}$` | 建议可选高级字段；空值由后端生成，用户不必输入标识即可创建 |
| 类型 | 必选，默认子 Agent | 使用“子 Agent / 主 Agent”中文标签 |
| 简介 | 可选，内容完整保存 | 用于识别职责，也可参与路由目录 |
| 提示词 | 必填，不接受空白串，长度不超过配置上限，默认 20000 | 明确职责、回答方式；保留已支持模板变量规则 |
| 可用工具 | 可为空，从后端目录多选 | 名称、用途、读/写标识；主 Agent 禁止写工具 |
| 可用技能 | 可为空，从后端目录多选 | 展示用途、适用类型和工具/检索依赖 |
| 关联子 Agent | 仅主 Agent 展示；启用时至少一个有效关联 | 候选为已发布且已启用的 WORKER；默认使用其简介作为使用场景，可编辑 |

“创建”一次提交完整定义，成功后进入详情并提示“已创建，启用后生效”。不自动启用，不要求用户再切换多个页签补填提示词或能力。失败保留全部已填内容并显示服务端错误。类型切为子 Agent 后清空隐藏的子关联配置。

### 4.3 编辑与启用

原有编辑页增加技能配置，详情准确回显全部创建字段。保留高级模型、MCP、提示模板、策略、历史版本功能。

“保存草稿”只保存配置；“启用”针对已保存草稿执行完整后端操作；若页面尚有本地未保存修改，应先保存或明确提示先保存，不允许静默启用旧内容。对于正在运行且有新草稿的 Agent，提供“发布更新”，成功后下一次调用使用新版本。

启用成功至少反馈已启用状态及版本；Runtime 被管理员显式关闭、校验失败、保存失败时，不得提示“已启用并可用”。失败不产生半完成版本、错误启用标记或 Registry 残留。重复点击应被前端抑制，后端保证并发操作的状态一致性。

允许停用被已启用主 Agent 引用的子 Agent，停用后不再进入新调度。运行时动态过滤已停用或不可用的子 Agent，不得绕回旧硬编码实现继续调用；没有可用子 Agent 时给出可读提示。重新启用或发布主 Agent 时，重新校验所有关联目标的可用性。

### 4.4 正式聊天入口

允许存在多个主 Agent。聊天页面提供已启用主 Agent 下拉选择，默认保持原有 `supervisor`；正式聊天 API 支持同样的显式主 Agent 标识。新主 Agent 启用后可在入口选中并实际调用关联的任意合法 Worker code。

显式选择不存在、停用或 WORKER 标识应给出错误，不得静默调用默认主 Agent。当前页面选项失效时应刷新或提示重新选择。默认请求兼容现有聊天使用习惯；配置 Runtime 默认启用，管理员显式关闭时明确显示当前模式并拒绝虚假的配置启用成功。

## 5. 技能生效契约

提供至少一个可验证的内置技能，建议覆盖提示指令、订单工具依赖、知识检索等现有能力。代码/名称/说明由架构设计最终列明，不要求任意编辑或安装技能。

1. 配置存储技能标识，草稿、发布、重启和回滚完整保留；旧配置没有 skills 时视为未选择，兼容已有数据。
2. 选中技能的指令实际加入该 Agent 模型请求的系统提示词；技能声明的工具依赖/知识检索必须真实应用。多个技能与直接选择的工具合并去重。
3. 页面必须说明技能带来的额外工具/检索权限；依赖可由后端自动合并，但不能成为绕过主 Agent 禁止写工具和已有确认规则的途径。
4. 未知技能、不适用当前类型的技能或非法依赖由服务端拒绝；移除并发布后停止注入/开放对应能力，其他直接选择的工具仍按配置生效。
5. 运行效果的测试证据应是实际调用链的提示内容、工具绑定或检索调用。只证明 JSON 包含技能名、或桩模型固定回答某句话，不足以证明技能已生效。

## 6. 后端硬约束与兼容

所有约束均需要服务端执行，不能只依赖隐藏控件。空白名称/提示词、非法 code、重复标识、未知工具/技能、错误类型、未知模板变量需明确失败。子 Agent 禁止携带 children；主 Agent 禁止自引用、重复引用、引用主 Agent、引用不存在/未发布/已停用目标。

编辑冲突需要返回可识别冲突，保留本地内容并引导刷新；并发发布/停用不得出现数据库版本与 Registry 不一致。注册表加载必须基于已成功持久化的发布版本。重启后恢复已启用发布版本，未发布草稿不进入运行；Seed 不应覆盖用户修改。

沿用 viewer/editor/publisher 权限：viewer 只读，editor 创建保存/校验/试运行，publisher 或 admin 可启用、发布、回滚、停用。界面与服务端权限一致。所有名称/简介/错误等文本按文本安全展示。

## 7. 验收矩阵

P0/P1 的开放缺陷阻止产品通过。以下为验收标准，执行结果由测试和产品报告填写；未执行、离线替代、环境受限应分别标记。

| ID | 级别 | 场景与通过标准 | 所需证据 |
| --- | --- | --- | --- |
| AC01 | P1 | 从页面一次填写名称、简介、提示词、工具/技能创建 WORKER；刷新后所有字段一致 | 页面流程及 API 持久化 |
| AC02 | P1 | 用户只填写业务字段可创建，无需自行编制 code；创建后未启用且 Registry 无项 | 页面与后端状态 |
| AC03 | P1 | 点击启用自动校验发布加载；无需重启；版本与 Registry/页面一致 | 启用接口、页面反馈、运行版本 |
| AC04 | P1 | 已启用 Agent 保存新草稿不影响运行，发布更新后下一次调用新提示词 | 实际模型请求或可靠调用链捕获 |
| AC05 | P1 | 工具勾选/取消发布后实际工具绑定改变，不可调用未授权工具 | 工具绑定/调用证据 |
| AC06 | P1 | 技能持久化、指令注入、依赖工具或检索真实应用；移除发布后对应行为消失 | 运行请求、能力调用及持久化 |
| AC07 | P1 | 只有主 Agent 可关联；合法已启用 Worker 可关联；绕过页面传非法关系拒绝 | 页面切换、负向 API |
| AC08 | P1 | 新建并启用自定义主 Agent，聊天页选中后正式聊天路由到其自定义子 Agent | 页面/API → Supervisor → Worker 轨迹 |
| AC09 | P1 | 显式错误/停用/WORKER 主入口被拒绝；不静默回落默认主 Agent | 正式聊天负向接口 |
| AC10 | P1 | 允许停用被主 Agent 引用的子 Agent，停用后 Registry 移除，运行时动态过滤；零可用子 Agent 时明确提示；重新启用子 Agent 可恢复，主 Agent 重新启用/发布时重新校验关联可用性 | 停用/启用/过滤路由/主 Agent 校验证据 |
| AC11 | P1 | 启用错误、持久化失败、并发冲突无部分成功或错版本残留；按钮请求期间防重 | 失败/并发自动化证据及 UI |
| AC12 | P1 | 本地实际进程重启后已启用配置和技能恢复、草稿不加载、Seed 不覆盖修改 | 重启前后数据库/Registry 对比 |
| AC13 | P1 | 空白/重复/未知工具技能/非法关系/模板输入报错并保留表单，不接受非法运行定义 | 负向 API、页面错误展示 |
| AC14 | P1 | viewer/editor 不可绕过启用/发布/停用权限；publisher 可完成 | 权限 API 与页面显隐 |
| AC15 | P1 | 默认启动配置模式可用；显式关闭时页面准确告知且不声称配置启用成功 | 默认及关闭配置测试 |
| AC16 | P2 | 列表搜索筛选、编辑回显、版本/回滚、试运行保持可用；旧数据兼容 skills 缺省 | 回归测试 |
| AC17 | P2 | 窄屏无无法触达的提交按钮；动态文本安全显示，错误信息可读 | 浏览器页面检查 |

## 8. 产品验收执行说明

测试工程师完成测试并移交报告后，产品 Agent 以 AC01–AC18 核对候选实现、关键页面任务流程和测试证据。真实远程 LLM/MCP 不可用时，可用可控兼容服务验证传递提示词、绑定工具、选择主 Agent 的链路，但报告必须注明“受控模型”，不能等同于真实模型回答质量或外部服务可用性。

若核心功能尚未执行验证、或存在 P0/P1，结论为“未通过/受限，待验证”；不得以文档、原型或新增测试文件替代运行证据。发现缺陷回派架构师，测试复测后再签署最终报告。
