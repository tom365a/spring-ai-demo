# Agent 页面配置交付计划

编制及收口日期：2026-09-10。负责人：项目经理 Agent。最终状态：S0–S6 已完成，本轮 Agent 页面配置闭环通过独立测试和产品验收。下方初始缺口保留为实施前基线，实际完成及验证边界见第 8、9 节。

## 1. 目标与范围

用户通过管理页面填写名称、简介、提示词，选择工具和技能，创建 Agent；仅主 Agent 可以关联子 Agent。创建后保持草稿，点击启用时后端完成校验、发布和运行时加载，无需重启。编辑草稿不得提前污染已启用版本。启用结果必须能够在真实对话入口使用并验证。

沿用现有 Spring Boot 单体及静态管理页面，不重新搭建前端工程。以现有配置模型、版本表、运行时注册表为基础补齐闭环。技能需有明确目录、配置持久化及运行时行为；不能仅展示复选框。本轮不将任意上传可执行脚本或外部技能市场作为默认范围。

最终验收范围由产品 PRD v1.0 固化；架构变更或发现新缺陷由项目经理登记对交付的影响。

## 2. 初始实现与缺口

| 项目 | 已有基础与检查证据 | 初始缺口/影响 | 优先级 |
| --- | --- | --- | --- |
| 管理页面 | `static/admin.html`、`static/js/admin-app.js` 已有列表、编辑、工具、子 Agent、版本、试运行 | 创建与编辑操作分散，启用状态不能代表已经加载；需要按用户任务整合创建表单 | P1 |
| 创建/启用 | `AgentDefinitionService.create` 默认 `enabled=true`，版本为空；页面启用仅调用 update | 新建即显示启用，却不存在可运行版本；点击启用不自动发布草稿 | P1 |
| 发布与注册 | `AgentPublishService` 已有快照版本、校验、注册表替换及启动加载 | 在数据库事务提交之前修改注册表，提交失败可能留下假成功；并发发布与更新需要验证 | P1 |
| 工具与技能 | `AgentDefinition.tools`、`LocalToolCatalog`、本地工具绑定已存在 | 模型无 skills 字段、无技能目录及执行语义；需贯穿前后端和版本快照 | P1 |
| 主子关系 | `AgentDefinition.children` 及路由基础存在 | Validator 仅对主 Agent 做部分检查，未明确拒绝子 Agent 关联子 Agent；对子项存在性、类型、可用性需严格校验 | P1 |
| 对话入口 | `AgentOrchestrator` 通过固定 code `supervisor` 读取主配置 | 新主 Agent 即使启用也无通用正式入口；需定义选择/入口规则 | P1 |
| 默认运行模式 | `application.yml` 与 `application-local.yml` 配置开关默认 false | 管理页面成功操作后正式聊天仍可能走固定 Agent；默认体验与配置入口需一致 | P1 |
| 本地持久化 | local 使用 `jdbc:h2:mem:cs` | 重启丢失新建配置，需要持久化或明确可复现持久化运行方式 | P1 |
| 自动化测试 | 初次检查未发现 `src/test` 目录 | 缺少创建、启用、下线、运行时一致性、非法输入、回归证据 | P1 |
| 管理权限 | Controller 检查客户端 `X-Admin-Role`，页面可选择角色 | 属演示角色机制，不是完整用户身份认证；部署边界需记录，避免误称生产鉴权已完成 | P2/范围风险 |

以上是静态检查结论，不代表已复现所有运行期缺陷。设计文档存在不等于功能已经完成。

## 6. 质量门禁

- P0：数据破坏、安全严重失控、系统整体不可用。P1：创建/启用/加载/运行主链路不可用、状态与实际运行严重不符、数据丢失、绕过主子关联硬约束。任何未关闭 P0/P1 均阻止通过结论。
- 所有用户核心验收项均需可追溯证据；环境不具备时记录“未执行/受限”，不能标记“通过”。
- 至少验证：字段回显；工具/技能保存且运行生效；仅主 Agent 关联合法子 Agent；草稿创建后未加载；点击启用后免重启进入运行时；编辑草稿隔离；禁用后不再可调度；非法/冲突请求无部分成功；重启恢复；已有功能回归。
- 涉及远程大模型、MCP 或数据库的结果与本地桩/离线测试分开记录。接口桩能够验证协议和调用链，不能证明实际模型效果。
- 新主 Agent 的正式入口行为须由产品明确并由测试验证，不能以注册表存在或试运行成功替代。
